# MMA-5771：忘却前夜 MAA 自动化资源

这是基于 MaaFramework 的《忘却前夜》自动化资源。目前包含：

- 同调率调查战斗：进入战斗后隐藏卡牌、开启 AUTO、三帧动态验证、复活弹窗和结算处理。
- 主线自动推剧情 Demo：选择最新关卡、进入关卡、跳过剧情、处理战斗/造物/商店/选项和结算。
- 自动战斗卡死恢复：三帧均高度相似时补点一次 AUTO，再次验证；仍静止则停止，避免无限乱点。

> 本项目不包含游戏本体和 MaaFramework 二进制文件。脚本按诊断环境的 1280×720 基准坐标设计，MaaFramework 会通过控制器适配游戏画面。

## 本次修复

诊断报告 `diagnostic_report_20260902_170502.zip` 和 `diagnostic_report_20260902_170624.zip` 暴露了两个独立问题。

### AUTO 点击位置错误

旧逻辑在 `[75, 510, 105, 60]` 区域识别静态 `AUTO` 字样，实际点击点为 `(103, 529)`。该位置属于左下角算力/计数区域，不是自动战斗按钮。由于静态文字始终存在，`AutoEnabled` 仍会被误判为成功，后面的三帧检测也不会按预期接管。

新逻辑：

1. 不再用 `auto_on_text.png` / `auto_off_text.png` 判断 AUTO 状态。
2. 固定点击实际按钮中心 `(148, 658)`，节点点击框为 `[140, 650, 16, 16]`。
3. 点击后强制采集三帧，间隔 1.5 秒。
4. 仅当两段帧差都低于 `0.0025` 时判定战斗静止。
5. 静止时只补点一次实际 AUTO 按钮，然后完整重做三帧验证。
6. 第二次仍静止即停止任务，防止反复开关 AUTO 或点击其它 UI。

### 剧情跳过没有触发

旧逻辑要求右上角播放图标和快进图标同时模板命中。诊断中播放图标得分约 `0.85`，但旧快进模板只有约 `0.29`，所以 `StoryCutscene` 一直失败，流程又继续尝试战斗、选项等状态。

新逻辑：

1. 使用诊断截图中真实显示的快进图标重新制作 `story_skip_live.png`。
2. 剧情状态在所有剧情内页判断中优先级最高。
3. 同时限定播放图标 ROI `[1080, 5, 82, 82]` 与快进图标 ROI `[1170, 5, 84, 82]`，避免章节详情页右上角单独的播放/关闭图标误触。
4. 命中后固定点击快进按钮有效区域 `[1196, 32, 28, 38]`。
5. 随后处理跳过确认，并重新进入剧情内页路由。

## 安装

### 覆盖到现有助手

1. 完全退出正在运行的助手。
2. 备份助手原有的 `resource` 目录。
3. 将仓库中的 `resource` 合并到助手对应的资源目录：
   - `resource/pipeline/*.json` 放入 pipeline 目录；
   - `resource/image/*.png` 放入 image 目录；
   - `resource/scripts/frame_motion.ps1` 放入 scripts 目录。
4. 重新启动助手并连接游戏窗口。
5. 游戏窗口使用 16:9 比例；推荐客户端渲染分辨率为 1280×720。

如果现有启动器使用多个资源包，请把本项目资源目录放在会被加载的资源搜索路径中，不要只复制 JSON 而遗漏图片和 PowerShell 脚本。

## AUTO 与三帧动态判定

`frame_motion.ps1` 的工作方式：

- 从当前截图裁出战场主体区域，排除左下角 AUTO/算力、右下角时间、顶部资源栏和调试标注。
- 将战场缩小到 96×54，以降低战斗特效噪声和 PowerShell 计算开销。
- 分别计算第 1→2 帧与第 2→3 帧的归一化 RGB 平均差。
- 两段差值都不超过阈值才返回“静止”；只要一段存在明显变化就认为战斗已经运行。
- 检测记录写入 `resource/scripts/.motion_state/*_motion.log`。

三帧判定不是在“认为 AUTO 已开启”之后可选执行，而是 AUTO 点击之后的强制门禁。只有动态验证成功，流程才会进入 `BattleMonitor`。

## 剧情流程优先级

剧情内页按以下顺序判断：

1. 剧情播放与右上角快进按钮；
2. 战斗编队/调查按钮；
3. 造物选择；
4. 商店；
5. 普通选项；
6. 战斗警报与战斗结算。

这样可以避免剧情播放期间被宽松模板误认成战斗、商店或选项页面。章节界面仍先选择最右侧的最新战斗/剧情关图标，进入关卡后才启用上述判断。

## 本地校验

需要 Python 3.9 或更高版本：

```bash
python tools/validate_resource.py
```

检查内容包括：

- Pipeline JSON 能否解析；
- `next` / `on_error` 指向的节点是否存在；
- JSON 引用的模板图片是否存在。

无需安装第三方 Python 包。

## 调试建议

如果 AUTO 仍未启动，请保留以下材料：

- AUTO 点击前、点击后以及三帧验证的截图；
- `resource/scripts/.motion_state/sync_motion.log` 或 `story_motion.log`；
- MaaFramework 的完整日志；
- 游戏实际渲染分辨率和 Windows 缩放比例。

如果剧情仍未跳过，重点检查右上角快进图标是否因游戏版本、语言或 UI 缩放发生变化。此时应重新裁取完整图标作为模板，不要降低全屏模板阈值，否则容易在章节地图误点。

## 已知限制

- 当前模板来自 2026-09-02 的简体中文客户端诊断截图；其他语言或重大 UI 改版需要重新采样。
- 固定坐标以 1280×720 基准画面定义，非 16:9 窗口可能导致控件偏移。
- 自动推剧情仍是 Demo，分支选择默认点击首个识别到的选项，暂不按剧情收益规划选项。
- 三帧阈值 `0.0025` 偏保守；若设备录屏噪声造成静态画面差值偏高，应根据 motion 日志微调，而不是绕过验证。

## 安全说明

本项目只通过 MaaFramework 进行截图识别和界面点击，不修改游戏进程内存或游戏文件。使用自动化工具前请自行确认游戏服务条款，并自行承担账号风险。
