# 忘却前夜同调率循环助手（MaaFramework 版）

当前版本：2.9.4-direct-auto-choice-fix

## 2.9.4 警告后固定决策链与剧情初始选项

- 完全删除同调率与剧情战斗的三帧动态判定及补点状态，不再根据画面差分决定是否进入战斗。
- 同调率固定流程改为：进入挑战 → 持续等待警告页面结束 → 延迟 4.5 秒 → 优先检测隐藏卡牌 → 若存在则点击隐藏卡牌 → 点击一次 AUTO → 进入战斗监控。
- 如果延迟结束后没有隐藏卡牌，直接点击一次 AUTO；进入战斗监控后不再点击隐藏卡牌或 AUTO。
- 新诊断中旧隐藏卡牌模板得分只有 `0.156952`。本版从同一实机画面的无标注区域重新制作 `hide_cards_live.png`，ROI 改为 `[1100,535,154,120]`。
- AUTO 继续使用上一版确认正确的 ROI `[25,470,85,60]` 和点击范围 `[45,485,28,24]`，不会点击下方算力 `0/9`。
- 剧情跳过完成后首先执行一次专用初始选项判断。该节点只要求出现一个放大镜选项标记，并按纵向选择最下方结果；随后恢复原有的严格多选项检测。
- 单选项检测只出现在 `StoryCutscene` 的直接后继中，不会在章节地图常驻，避免重新引入章节地图单图标误点。

## 2.9.3 AUTO 实际位置与剧情跳过修复

- 诊断截图确认真正的 `AUTO` 文字按钮位于 1280×720 基准画面的左下角约 `(59,497)`；旧 ROI `[75,510,105,60]` 向右下偏移，真实 AUTO 几乎不在识别范围内，导致模板在下方算力 `0/9` 区域误匹配，并点击 `(103,529)`。
- AUTO 识别范围改为 `[25,470,85,60]`，点击范围固定为 `[45,485,28,24]`，与算力计数区域完全分离。
- `speed.png` 对应左下角圆形双箭头倍速按钮，本版明确不再把它当成 AUTO 点击。
- 删除依赖错误 ROI 的 `AutoEnabled/EnableAuto` 亮暗状态链。检测到战斗 AUTO 控件后只点击一次，随后无条件执行三帧动态验证。
- 三帧两段画面均高度相似时才补点一次真正的 AUTO；补点后完整重做三帧验证，仍静止则导出诊断并停止，避免无限点击。
- 剧情内页将 `StoryCutscene` 提升为最高优先级；使用卡住现场重新裁取的 `story_skip_live.png`，同时验证播放与快进两个图标，然后点击右上角 `[1196,32,28,38]`。
- `interface.json` 中“不使用助战”“使用灵知”等选项覆盖已同步指向新 AUTO 状态，切换界面选项不会恢复旧逻辑。

## 2.9.2 章节入口隔离与三帧自动战斗判定

- 诊断报告确认章节地图的单个放大镜被旧 `StoryChoicePage` 以 0.6212 误判，导致还没有点击关卡就循环执行“最下面选项”。
- 自动推剧情改为两阶段状态机：任务入口只识别战斗/剧情关图标并选择最右侧的最新关卡；成功进入后，才启用编队、剧情播放、战斗、造物、商店和选项判断。
- 最新关卡选择器同时搜索战斗双剑图标和剧情播放图标，并按横向位置选择最右侧结果。点击成功后不会再回到入口状态，直到完成关卡或返回章节地图。
- 剧情选项页不再用单个放大镜作为判据，必须同时在上下两个选项区域检测到放大镜；章节地图右上角的单个放大镜无法满足条件。
- 同调率与剧情战斗新增真实三帧动态检测：连续采集 3 张 Maa 后台截图，每帧间隔 1.5 秒，总观察时间约 3 秒。
- 三帧比较只使用画面中央战斗区域，缩小成 64×36 灰度图后计算两组平均像素差。两组差值均低于 0.0025 才视为“相似度极高、战斗停住”。
- 若画面正在变化，直接进入战斗监控；若画面停住，仅在 AUTO 精确中心补点一次，然后重新采集三帧验证。
- 补点后仍然连续三帧静止时不会继续反复点击，而是停止任务并自动导出诊断报告，避免再次把 AUTO 点暗。
- 三张原始帧和计算结果保存在 `runtime\debug\motion`；`*_result.txt` 会记录两组帧差、阈值和 MOVING/STATIC 结果，并随诊断包一起导出。
- 自动诊断报告现在同时包含 `sync_rate.json` 和 `story_demo.json`。

## 2.9.1 AUTO 亮暗互斥与剧情跳过双锚点

- 诊断报告确认旧版首次正确点击灰色 AUTO 后，`auto_off.png` 在已经亮起的按钮上仍得到 0.9448 的误匹配分数，导致补点把 AUTO 关闭。
- 删除所有 AUTO 二次、三次补点节点。每轮战斗只允许灰色 AUTO 节点执行一次点击；点击后只等待验证，不再存在任何可再次点击 AUTO 的后继节点。
- AUTO 的 ROI 从错误的 `[0,460,140,75]` 移到实际按钮文字区域 `[75,510,105,60]`。旧 ROI 无法完整容纳真实按钮，却会在卡牌背景上得到假高分。
- 新增 `auto_on_text.png` 与 `auto_off_text.png`，只识别灰色/白色的 `AUTO` 四个字母，不再让相同的棕色按钮背景主导匹配分数。
- 开启状态必须同时通过白色文字模板和高亮颜色检测，并连续两帧确认；只有第二帧仍为白色才进入战斗监控。
- 剧情跳过不再单独识别右上角图标。现在必须同时匹配“播放三角形”和“快进三角形”两个锚点，才判定为剧情播放并点击快进。
- 章节地图右上角只有关闭图标，不满足双锚点条件，因此不会再被错误判定为剧情播放，也不会循环点击不存在的跳过位置。

## 2.9.0 自动推剧情 Demo 与可选助战

- MAA 任务列表新增“自动推剧情（Demo）”。请在剧情关卡列表、编队页或已进入的剧情/战斗事件页启动。
- 关卡列表会在窗口中部识别战斗图标或剧情播放图标：战斗关进入编队后点击调查；剧情关进入后识别并点击右上角跳过。
- 剧情战斗沿用“最高警报 → 隐藏卡牌 → 精确识别 AUTO → 严格战斗监控”的流程。进入监控后不再判断或点击隐藏卡牌和 AUTO。
- 战斗结束后统一判断：调查完成、应急灵知体弹窗、剧情选项、剧情播放、造物商店、造物三选一。每处理一个事件都会回到同一状态路由，支持连续出现多个事件。
- 剧情选项优先 OCR 点击包含“黄金造物”或“白银造物”的选项；没有匹配时点击最下面的选项。
- 造物商店支持“购买全部造物”或“只购买第一个造物”。全部模式按左、中、右顺序尝试；价格出现红字时点击取消并关闭商店。
- 造物三选一支持左、中、右三个设置。识别页面后点击选定卡片，等待按钮亮起，再点击下方确认。
- 剧情任务可独立设置是否使用应急灵知体；仍使用标题与正文双锚点严格识别。
- 同调率任务新增“是否使用助战”：默认继续执行严格助战门控；选择“不使用助战”后，点击挑战即直接识别并点击调查。
- 同调率 AUTO 从一次补点升级为最多三段精确验证。只有开战初始化阶段会重试；一旦进入 `BattleMonitor`，仍只等待灵知弹窗或调查完成。

> Demo 说明：图 1/2/3/6/7 按用户提供的“截图内容位于窗口中央”换算为 1280×720 坐标。首次实际运行建议保留诊断报告；遇到新章节布局或新商店样式可用报告继续校准。

## 2.8.2 循环助战强制门控

- 修复循环多次后编队页直接识别调查按钮、跳过助战的问题。
- `CycleStart` 点击挑战后只能进入 `OpenAssist`，不再把选择助战、上场、快捷编队或调查作为并列候选。
- `OpenAssist` 点击助战入口后只能识别助战列表；`ChooseFirstAssist` 选择角色后必须识别亮起的 `DeployAssist` 上场按钮。
- 只有 `DeployAssist` 成功点击后，其后继列表才包含 `StartInvestigation`。因此调查按钮无法绕过助战选择和上场确认。
- 快捷编队恢复仍保留为入口路由和异常恢复能力，但不再出现在正常助战链中抢占调查步骤。
- 入口路由和快捷编队恢复也不再直接连接调查按钮；即使从编队界面启动或误入快捷编队，也必须重新经过助战入口或已亮起的上场按钮。

## 2.8.1 应急灵知体弹窗严格识别

- 不再使用单独的“取消/确认”按钮作为弹窗存在判据；普通战斗界面的同色按钮不会再触发复活流程。
- 使用本次 2048×1149 原始截图制作两个独立锚点，并按 1280×720 标准识别：`复活确认` 标题阈值 0.86，`是否启用应急灵知体` 正文阈值 0.82。
- 只有两个锚点同时匹配成功（`And` 组合识别）才判定为应急灵知体弹窗。
- “直接退出”点击标题匹配框相对位置 `[-41,343,-292,-92]`，对应左侧取消按钮中心 8×8 区域；“使用灵知”使用 `[341,343,-292,-92]`，对应右侧确认按钮。点击点会跟随弹窗实际位置移动，不受窗口宽度变化影响。
- 右侧日志会明确显示双锚点判定成功以及最终点击的是确认还是取消。

## 2.8.0 严格战斗监控、超时停止与自动诊断

- `BattleMonitor` 已彻底移除隐藏卡牌、AUTO 和暂时撤退判定。进入战斗监控后只轮询两个结果：`ReviveDecision`（应急灵知体确认/取消弹窗）与 `FinishInvestigation`（调查完成）。
- 战斗监控使用单个连续 300000 ms 计时器；5 分钟内两种结果都未命中时，进入错误链，自动导出诊断报告并执行 `StopTask`，不会继续点击游戏。
- 其他流程节点继承统一超时错误链；原有 60–180 秒识别期限到达后停止任务并自动导出报告。AUTO、隐藏卡牌恢复、结算按钮等旧的超长等待已缩短为 30–60 秒。
- MAA 右侧运行日志现在通过 `focus` 显示：当前识别命中的节点、开始执行、执行成功、动作失败和节点超时。战斗监控会明确显示“只等待灵知弹窗或调查完成”。
- 自动报告名为 `diagnostic_report_auto_日期_时间.zip`，位于助手根目录；包含完整 `maafw.log`、匹配分数、阈值、标注截图、超时截图和实际 Pipeline。
- 识别的真实匹配分数与阈值仍完整保存在报告的 `recognition_scores.txt` 和 `debug\vision` 中。MFAAvalonia 的右侧消息模板只能可靠显示节点与判定结果，不能稳定展开嵌套的逐帧匹配分数，因此未伪造或省略报告中的原始精度数据。

## 2.7.3 隐藏卡牌状态修复

- 诊断报告显示流程依次进入了 `EnableAuto → EnableAutoRetry → AutoFinalWait → BattleMonitor`；隐藏卡牌当时尚未出现，而旧版 `BattleMonitor` 不再检查隐藏卡牌，因此按钮稍后出现也无法处理。
- “最高警报”消失后增加 4.5 秒过渡等待，覆盖奖励卡牌与回合初始化动画；过渡结束后优先判断隐藏卡牌，再判断 AUTO。
- 警报画面不再允许直接进入 AUTO 节点，避免灰色 AUTO 虽然可见但尚不可操作时被提前点击，并过早进入 `BattleMonitor`。
- 仍兼容不出现隐藏卡牌的情况：过渡等待结束后若没有隐藏卡牌，会继续识别并开启 AUTO。
- 2.7.3 曾在 `BattleMonitor` 中保留隐藏卡牌恢复；该设计已由 2.8.0 撤销。当前战斗监控绝不会再识别隐藏卡牌或 AUTO。

## 2.7.2 自动战斗状态修复

- AUTO 改为开战阶段的有限确认：首次点击失败时最多补点一次；识别到白色 AUTO 或补点后战斗画面已经切换，随后进入独立的 `BattleMonitor` 状态。
- 自动战斗状态不再包含 `AutoEnabled`、`EnableAutoRetry` 或隐藏卡牌节点，因此战斗画面变化后不会持续识别、反复点击 AUTO。
- 自动战斗期间只检查“确认/取消”“暂时撤退”和“调查完成”；只有选择使用灵知复活后，才重新执行一次 AUTO 开启与验证。
- MaaFramework 的纯 JSON 流程不提供前后两帧通用像素差分，本版本以“白色 AUTO 已确认”或“最多一次补点后经过 1.8 秒画面切换缓冲”作为进入自动战斗的稳定判据，达到画面明显变化后停止 AUTO 判定的效果。

## 2.7.1 AUTO 稳定性修复

- 诊断报告确认：灰色未开启 AUTO 曾被白色已开启模板以 `0.769–0.796` 的分数误判；旧阈值 `0.78` 会偶发把它当作已经开启。
- AUTO 识别范围收紧至标准 1280×720 画面的 `[0,460,140,75]`，仅覆盖左下角 AUTO 按钮，不再搜索角色和战斗背景。
- 未开启模板重新取自本次实际战斗画面；点击点固定在模板中心的 6×6 小范围内。
- `AutoEnabled` 状态现在会继续进入 `EnableAutoRetry`：若 AUTO 实际仍为灰色，会补点并再次验证，不会因一次误判永久停住。

## 首次启动

1. 完整解压本压缩包。
2. 启动《忘却前夜》，停留在主界面或“羽毛·癫狂”的挑战页面。
3. 双击 `START_WIN64.cmd`（也可以使用中文名 `启动_MAA助手.bat`）。窗口无论成功或失败都会保留，不会再闪退。
4. 首次运行会自动安装 .NET 10 Desktop Runtime x64，并准备官方 MFAAvalonia v2.16.0 Windows x64 运行包。
5. 在 MAA 界面选择控制器和识别到的“忘却前夜 Morimens”窗口，勾选“羽毛·癫狂同调率循环”后启动。

## Windows x64 启动排错

- 仅支持 64 位 Windows 10/11；启动器会强制调用 64 位 Windows PowerShell。
- PowerShell 安装脚本已使用 Windows PowerShell 5.1 可识别的 UTF-8 BOM 与 CRLF 编码，支持中文系统区域。
- 启动器优先使用 `deps` 中的离线依赖；缺失时自动下载到该目录，之后可离线重复启动。
- `.NET 10 Desktop Runtime x64` 使用静默安装，无需手动操作安装向导。
- 首次运行会校验 MFAAvalonia x64 压缩包，旧下载不完整时会自动重新下载。
- MFAAvalonia 若启动后立即退出，窗口会显示退出码。
- 详细信息保存在 `startup_win64.log`。若仍无法启动，请发送这个文件。
- 如果游戏以管理员权限启动，请右键 `START_WIN64.cmd`，选择“以管理员身份运行”。

## 后台控制器选择

- **后台增强·光标定位（推荐）**：`FramePool + SendMessageWithCursorPos`。不抢占前台窗口；点击时鼠标可能极短暂移动并立即恢复。适用于会检查真实鼠标位置的游戏。
- **纯后台·窗口定位**：`PrintWindow + PostMessageWithWindowPos`。不移动鼠标、不切换前台，但目标窗口可能轻微闪动。
- **纯后台·标准消息**：`FramePool + SendMessage`。完全不移动鼠标，兼容性相对较低。

三种模式都是 MaaFramework 官方 Win32 控制器提供的后台方法。不同 Windows 游戏的输入机制不同，没有一种方式对所有游戏通用；若第一种仍无响应，依次尝试第二、第三种。

## 稳定性改进

- 支持从主界面依次进入“活动 → 第一个活动 → 限时玩法 → 羽毛 → 癫狂”。活动页仅确认左侧存在活动卡片，随后固定点击第一项，不依赖活动标题或活动图片。
- 限时玩法按钮改为识别右下角双剑图标并点击识别结果，不再依赖固定按钮坐标。
- 助战选择后，只要仍识别到助战页面，就循环点击右下角“上场”区域，直到进入编队页。
- “上场”改为只点击按钮模板的识别中心，不再使用覆盖快捷编队的大范围固定坐标；若误入“选择唤醒体/快捷编队”，会自动识别标题并点击右侧空白区域退出，然后继续点击“调查”。
- 若误点头像进入角色详情，会先识别左侧“状态”标签，再单独识别右上角 X 图标并点击图标中心；未关闭时持续重试，关闭后返回助战页。
- 助战选择点进一步右移到第一行卡片中部偏右的稳定空白区（MAA 坐标 870,210），避开左侧角色立绘、右侧玩家头像和底部刷新按钮。
- “上场”“调查”“隐藏卡牌”和 AUTO 均先在各自的小范围 ROI 内识别按钮模板，再点击匹配框中心；不再给识别结果叠加坐标偏移。
- “上场”的 ROI 已修正到右下角 950–1205 区间，解决旧版 ROI 横向只到 960、实际按钮无法进入识别范围的问题。
- 固定位置点击矩形统一收缩为 8×8，显著降低后台点击在目标区域内的随机偏移。
- “羽毛”点击点向上移动到卡片标题区域，避开下方材料图标；若误点材料出现“活动货币”说明，会点击右侧空白处关闭并重新选择羽毛。
- 限时玩法双剑按钮点击后会验证是否进入下一界面；如果按钮仍存在，按较低频率重复点击，直到成功进入。
- 每个等待阶段都会检测可能提前出现的后续界面，支持从中间状态继续执行。
- 若 AUTO 未成功开启而重新出现“隐藏卡牌”，会再次隐藏卡牌并重新识别原有 AUTO 界面模板。圆形双箭头是倍速按钮，不参与 AUTO 判断。
- 新增“挑战失败处理”选项：默认直接退出；也可选择消耗应急灵知体复活并继续自动战斗。
- 所有模板统一按 MaaFramework 推荐的短边 720 分辨率制作。
- 每一步都有独立 ROI，避免全屏误匹配。
- “完成调查”同时使用两份按钮模板，阈值降至 0.48。
- 若结算按钮仍未匹配，会识别上方“调查完成”标题，并固定点击右下角按钮区域。
- 结算最长等待 30 分钟，普通加载节点提供 1–3 分钟等待。
- 每次完成调查后重新确认“挑战”按钮，形成闭环。

## 错误日志与截图报告

- 已默认开启完整日志、错误截图和识别可视化截图，无需手动配置。
- 完整日志：`runtime\debug\maafw.log`；备用日志：`runtime\debug\maafw.bak.log`。
- 每次识别的可视化截图：`runtime\debug\vision`，图中包含 ROI、命中位置、模板匹配分数和阈值。
- 流程失败时的原始截图：`runtime\debug\on_error`。
- 双击 `导出诊断报告.cmd` 会生成一个带时间戳的 ZIP，包含日志、错误截图、可视化识别图、当前流水线、模板和识别分数摘要。
- 每次启动会把上一轮 `runtime\debug` 移入 `runtime\debug_archive`，因此新导出的报告只包含本轮运行，避免旧截图和旧分数混入。
- “匹配分数”表示当前画面与模板的相似度；没有人工标注真值时不能计算统计学意义上的 precision，因此报告同时保留阈值和完整截图，便于判断误识别与漏识别。

## 本版点击区域审计

- 模板按钮：挑战、助战、上场、调查、隐藏卡牌、AUTO、完成调查、失败处理按钮均点击模板命中框中心，不附加位置偏移。
- 固定入口：主界面活动、第一个活动、羽毛、癫狂和助战卡空白区只使用 6×6 或 8×8 的小点击范围。
- 快捷编队恢复：识别“选择唤醒体”标题后点击 `(1050,140)` 的右上空白区；若标题仍存在会继续退出，不会直接判定任务失败。
- 调查按钮：按本次 2048×1164 截图重新缩放、重裁，并限定在右下角 ROI `[950,610,270,105]`。
- 诊断包复核：调查按钮曾以高分正确命中，但 MaaFramework 默认会在整个命中矩形内随机取点；现在所有模板按钮均通过 `target_offset` 收缩到中心 6×6 后再点击。
- 快捷编队阈值从 0.44 提高到 0.58，避免加载警告页背景以约 0.46 分误命中。
- 调查点击成功后不再检测快捷编队；加载警告、战斗过渡和卡牌选择阶段只等待隐藏卡牌、AUTO、失败或结算节点，避免跨阶段误点击。
- 第二份诊断包显示，正常战斗曾被“暂时撤退”以 0.555 分、被“止步于此”以 0.538 分误识别；现已禁止这两个节点从战斗阶段直接触发。
- 失败处理改为严格顺序：识别取消/灵知弹窗 → 暂时撤退 → 止步于此；“暂时撤退”仅检查下半屏弹窗区，“止步于此”仅检查右下角。
- 新增独立“挑战警告等待”状态：识别中央红色“警告”标题后不执行点击，每 2.5 秒复查；警告消失后再判断隐藏卡牌、AUTO、复活或结算。
- 第三份诊断包显示，加载中的“调查”按钮曾被两份蓝色“完成调查”按钮模板以约 0.58 分误识别；结算现改为必须先识别右上方“调查完成”标题，之后才点击右下角完成按钮。
- 蓝色按钮外观不再作为结算入口，因此编队加载、警告、战斗和隐藏卡牌阶段不会提前跳到下一轮。
- 第四份诊断包确认“隐藏卡牌”已以 0.748 分正确点击。后续曾误将圆形双箭头识别为 AUTO；v2.5.2 已恢复原有 AUTO 模板和判断范围，并将双箭头单独保存为 `speed.png` 倍速模板。
- 第五份诊断包显示，隐藏卡牌点击后等待 1.4 秒会错过 AUTO 可操作画面，之后旧模板只能以约 0.219 分误匹配左下角数字框。v2.6.0 将隐藏卡牌后的延迟缩短为 0.25 秒：优先识别未亮起 AUTO，识别失败时在精确中心位置补点；随后必须匹配白色 `auto_on.png` 才进入持续等待，否则经过 1 秒冷却后重试。
- 第六份诊断包纠正了上述判断：问题不是延迟，而是 AUTO 的 ROI 偏低。偏低的棕色背景被白色模板以 0.84–0.90 的假高分识别为“已亮起”，导致点击节点被跳过。v2.6.1 将未亮起和亮起 AUTO 的 ROI 统一上移并收紧为 `[0,420,220,130]`，改用颜色敏感的精确匹配；删除所有固定坐标补点，只有真实识别到 AUTO 后才点击其匹配框中心 6×6。
- 第七份诊断包显示，“取消”按钮以 0.520 分正确点击后，旧流程被写死在“暂时撤退”节点；即使已出现“调查完成”，也不会重新判断结算。v2.7.0 将战斗状态优先级统一为“确认/取消 → 暂时撤退 → 调查完成 → AUTO/隐藏卡牌”，每次处理确认或取消后重新进行完整状态判断。
- 结算改为两阶段严格点击：先识别右上角“调查完成”标题，再在右下角独立识别“完成调查”按钮并点击模板中心 6×6；点击后优先识别癫狂挑战页并从调查步骤继续循环。
