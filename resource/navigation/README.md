# 主界面与章节导航

识别主界面所有 UI 按钮，从主界面点击【调查】进入主线，在章节选择页拖动选章，进入章节关卡列表。模板直接从实机截图裁出（`samples/`），流程文件由脚本生成。

## 在助手里使用

两个新任务（`interface.json`）：

| 任务 | 选项 | 作用 |
| --- | --- | --- |
| 主界面按钮识别测试 | 主界面按钮（23 个） | 在主界面识别所选按钮并点击一次，用来核对每个按钮的识别和点击位置 |
| 进入主线章节 | 目标章节、关卡难度页签、到达关卡列表后 | 主界面 → 调查 → 选章 → 关卡列表；可从主界面、章节选择页或关卡列表开始 |

「到达关卡列表后」选【点击最新关卡并自动推剧情】会交给原有的 `StoryEntryRouter` 流程。

## 识别的内容

- 主界面：调查、唤醒体、编队、物资、幕间演习、学期课题、守密纪行、学籍档案、秘典书库、记忆回廊、幻梦深潜、相位对弈、融灾禁区、密境课堂、弥萨格商店、设置、主页图标、邮件、好友、左侧两个功能图标；两个活动横幅（内容每天变，只按固定位置点击，不做图像识别）。
- 小图标按钮（设置、主页、邮件、好友、左侧图标）要求同时识别到唤醒体/编队/物资，避免在其他页面误触发。
- 章节选择页：「调查行动」标题；关卡列表页：底部「共鸣/星级评分/关卡成就」栏；右上罗盘（返回）。

## 章节选择怎么走

没有 OCR，所以按「先回第 1 章、再数着往后拖」：向右连续拖 9 次（到头后不再变），再向左拖 N-1 次。目标章节中央的数字有模板时会校验，不一致就报错停止，不会进错章节。

**目前只有第 8 章有数字模板**（实机截图里只有它居中）。其余章节不校验，拖动次数不对就会进错章。补模板：在章节选择页让第 N 章居中，截图后运行

```
python tools/make_chapter_template.py 截图.png N
python tools/build_nav_pipeline.py
```

模板只裁数字的最后一位（前面的 0 每章相同）。模板作为第 9 章的数字时从侧卡裁的版本在居中时得分不够区分，所以没有保留。

## 调整

`nav_config.json`：拖动起止点和时长（`swipe`）、中央卡片点击区、难度页签和章节箭头位置、模板阈值。改完运行 `python tools/build_nav_pipeline.py` 重新生成 `resource/pipeline/navigation.json` 和 `resource/image/nav_*.png`（`--check` 可检查是否过期）。`nav_ui.json` 里是各个按钮在原截图中的位置。

## 测试

```
pip install MaaFw opencv-python-headless numpy
python tools/test_navigation.py
```

用 MaaFramework 在三张真实截图上跑流程（不需要游戏）：每个按钮在主界面命中并点击在按钮内，在其他页面不误触发；三个页面检测器只在各自页面命中；整个「主界面 → 选章 → 关卡列表」流程在第 1/5/8/9 章、从主界面和章节页开始时的拖动次数和终点正确；23 个按钮选项各自点到对应按钮。共 157 项。

## 没有验证的

- 只用了一台设备的三张截图（1596×898 左右，已缩放到 1280×720）。别的分辨率、画质、模拟器 UI 偏差未测。
- 一次拖动是否正好翻一章、拖动距离是否合适，只能实机测：测试里的假画面不会随拖动变化。章节页第 9 章之后显示「尚未解锁」，向右拖到头时的行为未知。
- 难度页签和章节箭头只按固定坐标点击，没有识别。
- 按钮上的「新」角标和红点在裁剪范围之外，但若角标位置和样本不同，识别分数可能下降。
- 「关卡列表」之后的剧情/战斗节点沿用原来的 `story_demo.json`，这次没有改。

## 密境课室与幕间演习

新增两个任务（`daily_ui.json` 描述识别内容，`tools/build_daily_pipeline.py` 生成 `resource/pipeline/daily.json` 和 `resource/image/daily_*.png`，样本在 `samples/`）：

| 任务 | 选项 | 做什么 |
| --- | --- | --- |
| 密境课室日常/周常领取 | 范围（日常+周常/仅日常/仅周常）、底部进度节点（点击/不点击） | 识别【日常试训】【周常试训】页，点击所有可见的任务【领取】（自上而下，每次点完关闭【获得物资】弹窗，直到没有蓝色领取按钮），再依次点击底部四个进度节点（250/500/750/1000），然后点左侧页签切到周常重复一遍 |
| 幕间演习一键领取/派遣 | 调查报告（再次派遣/关闭） | 点击派遣页左下角的一键按钮，关闭【获得物资】，在【调查报告】点【再次派遣】或【关闭】 |

两个任务都能从主界面开始（点【密境课堂】/【幕间演习】入口），也能从目标页面直接开始。

### 测试

```
python tools/test_daily.py
```

用 MaaFramework 在 5 张真实截图（日常、周常、幕间演习、获得物资、调查报告）和一张抹掉【领取】按钮的日常页上跑：每个节点只在对应页面命中；点击落在预期位置；日常+周常、仅日常不点节点、仅周常（从日常页起步）、幕间演习再次派遣、幕间演习关闭报告，5 个完整流程的节点顺序和点击都对。共 84 项。

### 没有验证的

- **底部进度节点**：礼盒「可领取/未达成/已领取」的外观没有样本（截图里进度都是 0），无法识别状态，只能按固定位置点击。未达成的节点点击后会出现什么（提示、弹窗）不清楚；每次点完会点空白处，但若出现需要别的关闭方式的弹窗，下一个节点会点不到。
- **任务【领取】后**是否出现【获得物资】弹窗没有样本（这张弹窗来自幕间演习），识别的是同一个标题；没有弹窗时流程照常继续。
- **一键按钮**在没有可领取任务时叫什么、是否还在同一位置没有样本；流程按固定位置点击，只要求页面标题和「派遣限制」标签在。点击后出现的其他确认弹窗没有处理。
- **再次派遣**之后是否有确认弹窗没有样本。
- 日常页在滚动列表下方还有任务，只处理屏幕上可见的【领取】；一次领不完时流程不会滚动列表。
- 另一个已知差异：几张样本的窗口边框不同，同一图标的位置相差几个像素，点击区域都留了余量。

## 校友会与信箱

两个新任务（`social_ui.json` 描述识别内容，`tools/build_social_pipeline.py` 生成 `resource/pipeline/social.json` 和 `resource/image/social_*.png`）：

| 任务 | 做什么 |
| --- | --- |
| 校友会点赞 | 主界面左上角校友会 → 「校友会 关注」列表 → 点第一位玩家头像 → 「守密人档案」点赞（选项可关闭）→ 点右上角罗盘逐级返回，识别到主界面为止 |
| 信箱全部领取 | 主界面信箱 → 点【全部领取】→ 关闭「获得物资」弹窗 → 返回主界面 |

可以从主界面或目标页面直接开始。点赞只在按钮是未点赞样式时点击，已点过赞的档案只返回。

测试：`python tools/test_social.py`，用 MaaFramework 在 5 张实机截图（关注列表、守密人档案、点赞成功、信箱、获得物资）加主界面上跑，共 81 项，含各节点只在对应页命中、点击位置、校友会/信箱两条完整流程、已点赞、弹窗需点两次才关闭。

没有验证的：
- 点击列表第一位玩家的**头像**是否会打开档案，没有样本（只有打开后的页面）；
- 「点赞成功」提示是否挡住按钮，以及点赞后返回会不会有确认弹窗；
- 点赞按钮的「未点赞」样式只有一个样本，已点赞后是实心拇指，没有框，流程据此判断；
- 罗盘在「点赞成功」那张截图里被窗口边缘截掉一部分，模板认不出，所以返回时会先识别罗盘、认不出就按固定位置点击，最多 6 次，直到识别到主界面；
- 信箱没有可领取邮件时【全部领取】的外观（可能置灰）没有样本，此时点击后流程照常返回；
- 返回主界面需要罗盘逐级返回的次数没有样本，按「点一次、检查是否到主界面」循环最多 6 次。

## 同调率循环：通用活动入口

`同调率循环` 任务原来的入口流程绑定了旧活动（点第 1 项 → 识别「限时玩法」图标 → 选羽毛/癫狂）。新活动的流程是：主界面横幅 → 活动页（左侧列表，右下两个玩法入口）→ 活动关卡页（横排节点，每个节点下有【掉落预览】）→ 点节点 →（原有的）挑战/助战/调查/战斗循环。现已改成与活动名称无关：

| 页面 | 怎么识别 | 设置项 |
| --- | --- | --- |
| 活动页 | 左上角「活动」标题（所有活动通用） | 活动列表项：保持当前选中（默认）/ 第 1–8 项 |
| 玩法入口 | 固定位置点击 | 右侧金色（默认，如追寻圣杯之旅）/ 左侧蓝色（如意识潜游） |
| 活动关卡页 | 节点下的【掉落预览】文字（所有活动通用） | 节点 1–5（默认 1） |

生成：`activity_ui.json` → `python tools/build_activity_pipeline.py` → `resource/pipeline/activity.json`。`ActivityScreen` 节点已从 `sync_rate.json` 搬到 `activity.json`（旧版用 0.43 的低阈值匹配列表边框，在主界面和关卡页也会命中，现改为识别「活动」标题）。旧的「限时玩法图标 → 选羽毛/癫狂」节点保留，旧活动仍然能走。

测试：`python tools/test_activity.py`，在 2 张新活动实机截图（活动页、活动关卡页）加主界面等页面上跑 77 项：各节点只在对应页命中；入口左右、列表第 1–8 项、节点 1–5 的点击位置；主界面 → 活动页 → 入口 → 关卡页 → 节点的完整流程（左右入口 × 节点 1/3 × 是否切换列表项）。

没有验证的：
- **点节点之后的页面没有样本**：假设会出现原有的【挑战】按钮（`CycleStart`），之后的助战/编队/调查/战斗流程假设和旧活动相同。若新活动在节点后多一层（例如选难度、选羽毛之类）会超时并导出诊断报告。
- 节点 5 只露出一半，点击可能无效；超过 5 个节点需要左右拖动，暂不支持。
- 活动列表项按位置选，没有按名称识别。活动增减会改变位置。
- 左/右入口按固定位置点击，不识别按钮文字；没有「玩法限时开放」之外状态（如未解锁、已结束）的样本。
- 「保持当前选中」依赖游戏从主界面进入时默认选中想要的活动（样本里是点了横幅后选中的）。
