# 路线规划：信息是否足够

结论：**拓扑层基本够用，效果层仍需实机核对。** 现有数据能为全部 108 张图规划出「从起点到最终战」的可行路线；`events.json` 增加了关卡级事件选项先验，但不能将事件分配到具体格子。

## 能做到的（已实测）

`python tools/plan_route.py --check` 对全部 108 张图跑了最短路：

- 108 张全部可达最终战（5-11 原先因漏识别一块裂纹石不可达，已修复，见 `VALIDATION.md`）。
- 其中 105 张在「每扇门消耗一把钥匙」的假设下也成立，其余只在「一把钥匙开所有门」下成立。
- 规划使用：蜂窝邻接、锈蚀门扉+钥匙、成对隧道、单行密道→密道出口、可选的必经格（`--collect`）和回避格（`--avoid`）。
- 示例：`python tools/plan_route.py 5-6` 输出逐格路径（含 row/col 和原图像素坐标）。

第一次实测时只有 67/108 可达，暴露并修正了几个数据问题：图标位置按类型有偏差导致区域被拆开、部分无图标格漏识别、善意的礼物/单把钥匙模板缺失、裂纹石被误当成障碍（它在 2-15、4-15 等图是唯一通路，已改为可走）。

## 不够的（需要补）

按格子数量统计（共 2853 格）各类效果的可信度，详见 `tile_effects.json`：

| 可信度 | 类型 | 格子数 |
| --- | --- | --- |
| 已确认 | `player`, `battle`, `event`, `searchlight`, `illusion`, `locked_door`, `rusty_key`, `detention` | 1223 (42%) |
| 只确认名称 | `elite`, `final_battle`, `story`, `enrollment` | 272 (9%) |
| 推断 | `contact`, `tunnel`, `oneway_in`, `secret_exit`, `plain`, `cracked_rock` | 843 (29%) |
| 排除法推断 | `meltmark`, `blackseal` | 253 (8%) |
| 来源未核实 | `purple_rift` | 36 (1%) |
| 不明 | `extract`, `red_flesh`, `honey_wine`, `unfinished_statue`, `kind_gift`, `mother_of_brood`, `proxy_rite`, `white_sail`, `inquisitor`, `strange_cyst`, `unknown_icon` | 226 (7%) |

具体缺口：

1. **功能不明的常见格**：`meltmark` 融痕（165 格）、`blackseal` 黑印（88）、`extract` 析出点（80）、`purple_rift` 紫蓝格、`red_flesh` 红色血肉格，以及各章专属格。融痕、黑印按排除法推断为商店/物资，没有来源直接证实。
2. **事件选项和结果**：维基抄本已提供 367 条事件、281 条可关联现有地图，236 条含可结构化的选项结果；地图上的 248 个通用事件格仍无法逐格对应这些事件。路线里遇到事件格，需要实机读取标题和选项再决定。
3. **代价数值**：`cost` 只是规划权重（战斗 3、精英 6、幻象 5……），不是血量或症状数。要做「少掉血」「少拿症状」的最优路线，需要真实数值。
4. **迷雾与视野**：游戏里未探索的格子被迷雾遮住，视野 1 格（探照灯 +2）。离线路线假设整张图可见，实机应当边走边重新识别，把离线路线当作先验，而不是一次性执行。
5. **传送方向与配对**：每张图隧道恰好 0 或 2 个、单行密道与出口数量逐图相等，所以按「成对」处理；隧道是否双向、传送后落在哪一格没有核对。
6. **钥匙规则**：每图最多 1 把钥匙却有最多 5 扇门，默认按「一把开所有门」；是否消耗没核对。
7. **战斗难度与强制战斗**：战斗/精英/最终战之外，哪些战斗可以绕开没有数据。
8. **识别误差**：无图标格（空白、裂纹石、紫蓝、血肉）识别可信度较低，未逐格人工校对，详见 `VALIDATION.md`。

## 建议的下一步

- 在实机上走几张图，将当前事件标题与 `events.json` 的关卡候选匹配，再核对实际选项和传送去向；同时把未确认格的效果记入 `tile_effects.json`。
- 实机路线执行前，用 `tools/recognize_map_tiles.py` 对实机截图重新识别（需缩放到格子宽约 208 像素，未测试），再对照 `maps.json` 定位。
- 先从最常见的未确认格（融痕、黑印、析出点）入手，它们占了最多的格子。

## 2026-10 规划逻辑更新（客户端地图 + 导航修复）

规划器 `tools/plan_route.py` 和代理里的 `Navigator` 现在默认用客户端地图（见 README「客户端地图数据」）：
- **精确的地形**：墙不是格子、空地是 plain，不再有误识别的格子；代理里 `Knowledge.maps` 对能对上的 108 个旧 key 直接换成客户端布局，其余按客户端地图 id 或关卡名（`Knowledge.resolve_map`）取。
- **监察点**：不能走过去（8-2 实机：离开会回到上一格），唯一的出路是可选的「诈降」传送到羁押点（代价 `route.checkpoint_penalty`，默认 4，相当于一个症状）。8-2 的规划路线因此是：战斗 → 探照灯 → 监察点 → 羁押点 → 空地 → 审查会探员 → 战斗 → 联络点 → 最终战，与实机一致。
- **随机变体**：一格有多个随机变体（607 格，337 格类型不同）时代价取平均。
- **强制传送模型修正**：以前学到「踩上入口就强制传送」后，落点（对端隧道格）被当成又一个入口，路线断掉；现在落点是普通起点，路径里保留要点击的入口格。这让按"强制传送"假设会无解的地图从 207 张降到 22 张，模拟成功率从 97% 提到 99.9%（841 次）。
- **没钥匙点门不再拉黑**：没拿钥匙时门拒绝进入不算格子坏了，不会把门永久加入黑名单；拿到钥匙后清空门的失败记录。
- **推测桥接**：目标岛屿和起点之间没有任何已知连接时，在最近格之间加推测边（标 `speculative`），其余图保持原样。

模拟（`python -m morimens_logic.sim --maps client --seeds 1 [--optional-teleport]`，全部 863 张有最终战的客户端地图）：入口不强制传送 846/863 成功（98.0%，剩下 17 张是起终点在不相连岛上的图，模拟里没有它们的连接）；强制传送 840/841（99.9%，22 张按该假设无解的被跳过）。

没有验证的部分：除 8-2 外，规划路线没有实机验证；传送是否强制、钥匙能开几扇门、恶沼/造物等新格子的真实代价都是推断；模拟里的战斗和事件是随机模型。
