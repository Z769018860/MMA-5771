- `events.json`：367 条事件均有选项；没有指向不存在地图的链接；281 条关联到地图（`wiki_map_field` 210、`chapter_inferred` 44、`stage_filename_match` 27），86 条未关联；2 条事件名为「未知」；`3-5` 的「制作陷阱」重复。

## 事件数与地图识别互相印证

把每张忘却篇地图的「事件格数」与关联到的维基事件数对照（86 张有关联事件的图）：

| 对照方式 | 吻合 |
| --- | --- |
| 只数事件格 | 60 / 86 |
| 第 7 章加孕育之母，第 8/9 章加入学仪式与审查会探员 | 79 / 86 |

第 1–6 章几乎逐图吻合（8/8、10/12、9/9、12/12、9/10、10/10），说明事件格识别基本可靠。第 7 章每张图都有 1 个孕育之母，且事件数比事件格多 1（11/12），第 8、9 章的差值与入学仪式、审查会探员的个数吻合（7/10、3/3），所以这三种专属格很可能会触发事件。该结论只来自计数规律，已按 `inferred_from_counts` 写入 `tile_effects.json`，没有实机验证。其余没吻合的图（2-8、2-10、5-3、7-15、8-3、8-4、8-5 等）要么是链接按章节推断，要么是漏识别或事件不对应格子，没有逐个排查。

事件仍然只到「关卡级」：同一关的多个事件无法对应到具体格子，进入事件格后需要实机读标题再匹配。

## 5-11：已解决

原因：起点被两扇锁门（1,7）、（2,10）围住，唯一不用开门的出路是西南方的一块裂纹石（2,8），它被邻格完全包围，被「地块在黑色迷雾里」的判定误排除，于是起点区域只剩 2 格，钥匙在门后，路线判不可达。

修复：`classify_site` 对已有 ≥2 个已知邻格的位置不再要求周围有迷雾；紫蓝格仍要求在迷雾内（否则蓝色背景会被误认成 19 格紫蓝格，已在 8-11、9-12 上验证并避免）。

结果：新增 3 格裂纹石，5-11 路线为 起点 → 裂纹石 → 战斗 → 战斗 → 裂纹石 → 精英 → 裂纹石 → 联络点 → 事件 → 锈蚀钥匙 → 单行密道 → 密道出口 → 联络点 → 最终战。同一改动还补出另外 22 张图的 1–4 格（多为裂纹石、个别空白格和红色格），共新增 34 格，`maps.json` 现为 2887 格。目测 5-11 与 6-2 的新增格位置正确，其余未逐一检查。

## 第二轮：无图标格与事件数对不上的地图

### 无图标格排查

做法：把全部无图标格（空白、裂纹石、紫蓝、红色）裁成缩略图逐类目测，并枚举「与已识别格相邻、亮度像地面但没被识别」的位置逐个目测。

发现并已修复：

- **漏识别**：3-1、3-2、3-4 各漏 1 个析出点（图标变体，已补模板）；第 7 章的「碎石」型裂纹石（石块间有深色缝隙）漏识别（7-10 ×2、7-11、7-4、7-7、7-6 各 1），7-7 还漏 1 个紫蓝格。这类格子被四周的已知格包围，现在对被 ≥2 个已知格包围的位置放宽判定。
- **误判（已删除）**：把纸张/背景斑块当成格子：空白格 扭曲核心02 ×2、血与沙02 ×1、骑士的愿望03 ×1、8-4 ×1（右侧背景）；裂纹石 骑士的愿望03 ×3、血与沙02 ×1、1-13 ×1；紫蓝格 8-11 ×5、9-12 ×2、9-2 ×1（蓝色背景）。规则：背景斑块没有石面纹理（梯度能量低），裂纹石和紫蓝格要求纹理足够强；第 7 章米色空白格本身很平滑，所以只对低饱和度的平滑块做这条排除。
- 第一轮的 7-7 紫蓝格、5-11 的 3 块裂纹石、34 个补出格，在这一轮的目测中未发现错误。

结果：`maps.json` 现为 2879 格（空白 291、裂纹石 148、红色血肉 61、紫蓝 29）。108 张路线检查仍全部可达。

仍然可疑：6-10 的一格空白（行 5 列 1）是米色平滑块，与第 7 章米色空白格的特征无法区分，保留，未确认；7-6 的一格空白（行 1 列 16）同理。其余无图标格抽查的缩略图都像真实地块，但没有逐格看大图。

### 事件数对不上的 7 张图

| 地图 | 事件格 / 维基事件 | 观察 | 判断 |
| --- | --- | --- | --- |
| 5-3 | 2 / 3 | 多出的一条名为「未知」，图片名是 `UI_Dbgcopy_Image_MAP_009`（调试占位图） | 占位事件，不对应地图格；事件格数与真实事件数一致 |
| 2-8 | 6 / 7 | 多出的「亮晶晶」正是该图析出点格子的标签名 | 该图的析出点按「事件」处理；其他图的析出点没有这个规律 |
| 2-10 | 3 / 2 | 两条事件都是按章节推断（`chapter_inferred`）关联的 | 关联不可靠，可能漏了一条事件 |
| 7-15 | 2 / 1 | 其余 11 张第 7 章图都是「事件格数 + 1 个孕育之母」，只有这张例外 | 该图孕育之母可能不触发事件，或维基漏记 |
| 8-3、8-5 | 4 / 5 | 两张图的事件里都同时有「监察点」和「审查会探员」 | 审查会探员格可能触发两条事件（8-5 的关联是按章节推断） |

结论：事件格识别本身没发现错误，对不上的主要是「事件列表与特殊格的对应规律」不是处处成立（7-15、8-4 说明孕育之母、入学仪式不一定是事件），以及部分关联按章节推断。`tile_effects.json` 里这三种特殊格的「触发事件」仍是 `inferred_from_counts`，不是确认。
